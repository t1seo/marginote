# Real Obsidian demo capture

`node scripts/demo/record.mjs --check` verifies local prerequisites, the six shared sample files, and their links without connecting to Obsidian.

Run `node scripts/demo/record.mjs --record --expected-build-sha256=<verified-main.js-sha256>` only after the final candidate passes QA and the coordinator releases the isolated app for this recording. The script checks the installed bundle hash before connecting and after capture. It uses `connectQa()` to validate both the receipt and the real vault path. It imports the original English Markdown/SVG files from [the shared reading sample](../../examples/reading-vault/README.md) into a new `Marginote Demo` folder, or the next available numbered name. Only copied link prefixes and card IDs change. Existing files are never overwritten.

The sequence shows the default **Near text · follows pointer** behavior in Reading View and Live Preview. After a short text/image introduction, each view uses the existing **an illustrated note** link for a left → below → right path, 150 pixels from the link's boundary at every stop. This is the last eligible link before the long Lorem ipsum section, so another lower link does not take priority. The shared sample is unchanged. Assertions check the pointer stays inside the reading pane, the same mixed card remains passive, and the real card and connector move with it; all three measured states are retained in the behavior receipt. The recording then selects **Over link · stays in place**, demonstrates a stationary hover card and click pinning, scrolls through varied Lorem ipsum paragraphs to a lower anchor, and changes the preview-content setting to ordinary notes.

The target is 30–40 seconds, using a 1200×800 viewport, 100% Electron zoom, light theme, and collapsed sidebars. The host labels, sample titles, and captions are English; the scrolling passages are Latin filler. Old timestamped fixtures cannot appear in the recording.

The isolated vault's spelling checker is temporarily disabled so Latin filler does not fill Live Preview with spelling underlines. The recorder captures its original effective value and whether a vault override existed, restores both, and checks equality before disconnecting. This is a recording preference, not a change to the plugin or sample text.

Reading View can virtualize off-screen paragraphs. The scroll chapter uses wheel input before checking the lower link's presence and matches its unique alias plus destination instead of assuming a particular DOM index.

CDP captures page pixels without the operating-system pointer. A temporary cursor follows the actual `pointermove` coordinates, and chapter captions identify the modes. They are documentation overlays only. The recorder removes their listeners and DOM nodes, then captures five clean directory screenshots: text, image, mixed, ordinary note, and settings. Those PNGs contain no documentation overlay, are exactly 1200×800, and must each be below 5 MB.

Captions normally occupy the gap at top 70 pixels. A temporary animation-frame task moves them to the bottom during settings or when a card/annotation outline would intersect them. Each chapter marker asserts zero intersections, and sampled layout counts are saved as `session.captionLayout`. The task is cancelled when the overlays are removed. This prevents recording captions from hiding product content while the card moves.

The previous active note, preview preferences, theme, zoom, sidebars, and viewport are restored before CDP disconnects. Restoration assertions compare the saved state. SHA-256 checks verify that existing notes/images and the prepared sample files remain unchanged; `.obsidian` application state is excluded from content hashing. The new sample is retained rather than automatically deleting notes or images.

When explicitly requested, add `--leave-sample-open` to perform those restoration checks, then leave the newly generated sample at the top in Reading View with **Annotation cards only + Near text · follows pointer**. The deliberate final-view exception is recorded separately in the session metadata. The clean settings screenshot uses these same defaults.

Raw JPEG frames and capture timestamps remain under ignored `.qa/demo-<timestamp>/`. Before a new capture, the current MP4, GIF, poster, and metadata are copied into that directory's `previous-media/`; earlier raw directories remain untouched. Actual capture intervals produce an ffconcat input; ffmpeg generates `docs/demo/marginote.mp4`, a palette GIF targeting less than 5 MB (hard ceiling 10 MB), `poster.png`, and `recording.json`. Full MP4 and GIF decoding must pass. Thirteen intermediate MP4 frames, including all three directions in both views, the scrolling body, and the lower card, are extracted for visual inspection. They must be inspected, along with the listing images, before the demo is declared ready. Measured cadence, frame delays, file sizes, runtime versions, language checks, screenshot dimensions, behavior measurements, and session cleanup are recorded in JSON.

Existing personal vaults, third-party editorial assets, and other Obsidian instances are out of scope. This is a real application recording; the script does not replace the app with a browser mock or manufacture plugin UI.
